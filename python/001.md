# Python Topic 1 — Core Object Model & Data Structures

> **Interview focus:** Python references, identity, mutability, function arguments, hashability, dictionaries/sets, and copying.

---

## 1. Python Object Model

### Everything in Python is an Object

In Python, values such as:

```python
10
"hello"
[1, 2, 3]
{"a": 1}
```

are objects.

Variables are **names/references to objects**, rather than boxes containing values.

```python
a = [1, 2, 3]
```

Conceptually:

```text
a ───────→ [1, 2, 3]
```

The variable `a` refers to the list object.

---

## 2. Assignment Does Not Copy an Object

Consider:

```python
a = [1, 2, 3]
b = a
```

Both variables refer to the **same object**:

```text
a ─────┐
       ↓
    [1, 2, 3]
       ↑
b ─────┘
```

Therefore:

```python
print(a is b)
# True
```

If we mutate through `b`:

```python
b.append(4)

print(a)
# [1, 2, 3, 4]

print(b)
# [1, 2, 3, 4]
```

### Key Point

```python
b = a
```

does **not** create a copy.

It simply creates another reference to the same object.

---

# 3. `is` vs `==`

This is a very common interview question.

## `is` — Identity

`is` checks whether two variables refer to the **same object**.

```python
a = [1, 2]
b = a

print(a is b)
# True
```

---

## `==` — Equality

`==` checks whether two objects are **equal in value/content**.

```python
a = [1, 2]
b = [1, 2]

print(a == b)
# True

print(a is b)
# False
```

Here:

```text
a ──→ [1, 2]

b ──→ [1, 2]
```

The lists contain the same values but are different objects.

### Interview Rule

> `is` → object identity
> `==` → value equality

---

## `is None`

For singleton objects such as `None`, use:

```python
if value is None:
    ...
```

rather than:

```python
if value == None:
    ...
```

`is` is specifically checking identity with the singleton `None`.

---

# 4. Mutable vs Immutable Objects

## Mutable Objects

A mutable object can be **modified after creation**.

Common examples:

```text
list
dict
set
```

Example:

```python
a = [1, 2, 3]

a.append(4)

print(a)
# [1, 2, 3, 4]
```

The existing list object was modified.

---

## Immutable Objects

An immutable object **cannot be modified after creation**.

Common examples:

```text
int
float
str
tuple
bool
```

For example:

```python
x = 10
x = x + 1
```

The integer object `10` is not modified.

Instead, Python creates/references another integer object representing `11`, and `x` is rebound to it.

### Important Wording

Do not say:

> "An immutable variable cannot change."

Say:

> **"An immutable object cannot be modified after creation."**

A variable can always be **reassigned**.

```python
x = 10
x = 20
```

The variable `x` changed what object it refers to; the integer `10` itself was not modified.

---

# 5. Immutable Containers Can Contain Mutable Objects

A common interview trap:

```python
x = (1, [2, 3])
```

The tuple itself is immutable.

Therefore:

```python
x[0] = 5
```

raises:

```text
TypeError
```

But the list inside the tuple is mutable:

```python
x[1].append(4)
```

This is allowed.

Now:

```python
print(x)
```

gives:

```python
(1, [2, 3, 4])
```

### Key Concept

> Immutability of a container does not necessarily mean that every object contained inside it is immutable.

---

# 6. Function Arguments — Pass by Object Reference / Sharing

Python's argument passing is often described as:

> **Pass-by-object-reference**

or

> **Pass-by-sharing**

When an object is passed to a function, the function parameter becomes another reference to that object.

---

## Mutable Object Example

```python
def modify(x):
    x.append(4)

a = [1, 2, 3]

modify(a)

print(a)
# [1, 2, 3, 4]
```

Conceptually:

```text
a ───────┐
         ↓
      [1,2,3]
         ↑
x ───────┘
```

`x.append(4)` mutates the same list object.

Therefore the caller sees the modification.

---

## Immutable Object Example

```python
def modify(x):
    x = x + 1

a = 10

modify(a)

print(a)
# 10
```

Inside the function:

```python
x = x + 1
```

does not modify integer `10`.

Instead, `x` becomes a reference to a new integer object:

```text
Before:

a ──→ 10
       ↑
       x

After x = x + 1:

a ──→ 10

x ──→ 11
```

The caller's `a` remains unchanged.

---

# 7. Mutation vs Reassignment

This distinction is extremely important.

## Mutation

Mutation changes the existing object.

```python
x.append(4)
```

If another variable refers to the same list, it sees the change.

---

## Reassignment

Reassignment changes what a variable refers to.

```python
x = x + [4]
```

For lists, this creates a new list and rebinds `x`.

Example:

```python
def modify(x):
    x = x + [4]

a = [1, 2, 3]

modify(a)

print(a)
# [1, 2, 3]
```

The original `a` was not modified.

### Compare

```python
x.append(4)
```

vs

```python
x = x + [4]
```

First:

```text
mutates existing object
```

Second:

```text
creates new object + rebinds x
```

---

# 8. Hashability

Hashability is important for:

* dictionaries
* sets

A dictionary key must be **hashable**.

A set element must also be **hashable**.

---

## Common Hashable Types

Examples include:

```text
int
float
str
bytes
tuple (if all elements are hashable)
frozenset
```

---

## Common Unhashable Types

Examples:

```text
list
dict
set
```

These cannot be used directly as dictionary keys.

Example:

```python
d = {}

d[[1, 2]] = "value"
```

This raises:

```text
TypeError: unhashable type: 'list'
```

---

# 9. Why Does a Dictionary Need Hashable Keys?

A dictionary internally uses hashing to efficiently locate keys.

Conceptually:

```text
key
 ↓
hash(key)
 ↓
hash table location
```

Therefore, a key needs a stable hash value.

If the key could change in a way that affects its hash/equality after insertion, dictionary lookup could become inconsistent.

### Interview Definition

> An object is hashable if it has a hash value that remains stable during its lifetime and supports consistent equality comparison.

---

# 10. Tuple Hashability

A very common interview trap is:

> "Are tuples always hashable?"

**No.**

A tuple is hashable only when its elements are themselves hashable.

### Example

```python
d = {}

d[(1, 2)] = "A"
```

This works because:

```text
1 → hashable
2 → hashable
(1, 2) → hashable
```

But:

```python
d[[1, 2]] = "B"
```

fails because a list is unhashable.

---

## Important Tuple Trap

This:

```python
x = (1, 2, 3)
```

is hashable.

But:

```python
x = (1, [2, 3])
```

is **not hashable**.

Why?

The tuple contains a list, and the list is unhashable.

### Remember

> **Tuple immutability does not automatically make every tuple hashable.**

# 11. Assignment vs Shallow Copy vs Deep Copy

This is one of the most important areas when dealing with nested data structures.

Import:

```python
import copy
```

---

## Assignment

```python
a = [1, 2, 3]
b = a
```

No copy occurs.

```text
a ─────┐
       ↓
    [1,2,3]
       ↑
b ─────┘
```

Therefore:

```python
a is b
# True
```

---

# 12. Shallow Copy

A shallow copy creates a **new outer object**, but nested objects are still shared.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
```

Conceptually:

```text
a ──→ [ ──→ List A [1,2]
       └──→ List B [3,4] ]

b ──→ [ ──→ List A [1,2]
       └──→ List B [3,4] ]
```

The outer lists are different:

```python
a is b
# False
```

But nested lists are shared:

```python
a[0] is b[0]
# True
```

Therefore:

```python
b[0].append(10)
```

changes the nested list seen by both:

```python
print(a)
# [[1, 2, 10], [3, 4]]

print(b)
# [[1, 2, 10], [3, 4]]
```

---

# 13. Deep Copy

Deep copy recursively creates copies of nested objects.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)
```

Now:

```python
a is b
# False

a[0] is b[0]
# False
```

Changing a nested object does not affect the other:

```python
b[0].append(10)

print(a)
# [[1, 2], [3, 4]]

print(b)
# [[1, 2, 10], [3, 4]]
```

---

# 14. Assignment vs Shallow vs Deep Copy — Summary

| Operation          | Outer object | Nested objects |
| ------------------ | ------------ | -------------- |
| `b = a`            | Same         | Same           |
| `copy.copy(a)`     | New          | Shared         |
| `copy.deepcopy(a)` | New          | New            |

### Easy Memory Trick

> **Assignment shares everything.**
> **Shallow copy shares nested objects.**
> **Deep copy recursively copies nested objects.**

---

# 15. Flat vs Nested Collections

Consider:

```python
a = [1, 2, 3]
b = a.copy()
```

Since the elements are immutable integers, modifying the copied outer list is independent:

```python
b.append(4)

print(a)
# [1, 2, 3]

print(b)
# [1, 2, 3, 4]
```

But with nested mutable objects:

```python
a = [[1, 2], [3, 4]]
b = a.copy()
```

the nested lists are shared.

Therefore:

```python
b[0].append(10)
```

also affects `a[0]`.

---

# 16. Nested Tuple Example

Consider:

```python
x = (1, [2, 3])
y = (1, [2, 3])
```

`x` and `y` are separate tuple objects:

```python
x is y
# False
```

But their values are equal:

```python
x == y
# True
```

The nested lists are also separate because they were independently created:

```text
x ──→ tuple ──→ list A [2,3]

y ──→ tuple ──→ list B [2,3]
```

Therefore:

```python
x[1].append(4)
```

only modifies the list inside `x`.

Final state:

```python
x
# (1, [2, 3, 4])

y
# (1, [2, 3])
```

# 17. Common Interview Traps

## Trap 1 — `is` vs `==`

Wrong:

> `is` checks whether values are equal.

Correct:

> `is` checks object identity, while `==` checks equality.

---

## Trap 2 — Assignment Creates a Copy

Wrong:

```python
b = a
```

creates a copy.

Correct:

```python
b = a
```

creates another reference to the same object.

---

## Trap 3 — Immutable Variable

Wrong:

> An immutable variable cannot change.

Correct:

> An immutable object cannot be modified, but a variable can be rebound to another object.

---

## Trap 4 — All Tuples Are Hashable

Wrong:

> Every tuple can be a dictionary key.

Correct:

> A tuple is hashable only if all of its elements are hashable.

---

## Trap 5 — Shallow Copy Copies Everything

Wrong:

> `copy.copy()` recursively copies nested objects.

Correct:

> Shallow copy creates a new outer object while retaining references to nested objects.

---

## Trap 6 — Tuple Means Everything Inside Is Immutable

Wrong:

> A tuple cannot contain mutable data.

Correct:

> A tuple is immutable, but it can contain mutable objects such as lists.

# 18. Interview-Ready Answers

### Q: What is the difference between `is` and `==`?

> `is` checks whether two references point to the same object, whereas `==` checks whether two objects are equal in value.

---

### Q: Is Python pass-by-value or pass-by-reference?

A good Python-specific answer:

> Python uses pass-by-object-reference, also called pass-by-sharing. The function receives a reference to the same object. If the object is mutable, the function can mutate it; if it is immutable, operations that appear to modify it result in a new object/rebinding.

---

### Q: Why does modifying a list inside a function affect the caller?

> Because the function parameter and the caller's variable reference the same mutable list object. Mutating that object through the parameter is visible to the caller.

---

### Q: Why doesn't `x = x + 1` modify the caller's integer?

> Integers are immutable. The expression creates/references a new integer object, and the local variable `x` is rebound to it. The caller's reference remains unchanged.

---

### Q: Can a tuple be a dictionary key?

> Yes, provided all of its elements are hashable. A tuple containing a list, for example, is not hashable.

---

### Q: Difference between shallow and deep copy?

> A shallow copy creates a new outer object but shares references to nested objects. A deep copy recursively creates independent copies of nested objects as well.

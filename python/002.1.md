# Python 2.1 — Functions Fundamentals

## 1. Functions as First-Class Objects

In Python, functions are objects and can be treated like other values.

A function can be:

* Assigned to a variable
* Passed as an argument
* Returned from another function
* Stored in collections

### Example

```python
def greet(name):
    return f"Hello {name}"

f = greet

print(f("Mohit"))
# Hello Mohit
```

Here:

```python
f = greet
```

does **not** execute the function.

Both `f` and `greet` refer to the same function object.

```python
print(f is greet)
# True
```

### Important distinction

```python
f = greet
```

→ stores a reference to the function.

```python
f = greet()
```

→ executes the function and stores its return value.

---

# 2. Parameters vs Arguments

```python
def greet(name, age):
    print(name, age)
```

`name` and `age` are **parameters**.

When calling:

```python
greet("Mohit", 25)
```

`"Mohit"` and `25` are **arguments**.

### Remember

```text
Parameter → defined in function declaration
Argument  → supplied during function call
```

---

# 3. Positional Arguments

Arguments can be supplied based on position.

```python
def greet(name, age):
    print(name, age)

greet("Mohit", 25)
```

Binding:

```text
name → "Mohit"
age  → 25
```

---

# 4. Keyword Arguments

Arguments can also be supplied using parameter names.

```python
greet(name="Mohit", age=25)
```

This is called keyword argument passing.

Positional and keyword arguments can be mixed:

```python
greet("Mohit", age=25)
```

But positional arguments cannot come after keyword arguments.

```python
# ❌ Invalid
greet(name="Mohit", 25)
```

---

# 5. `*args`

`*args` collects additional positional arguments into a **tuple**.

```python
def process(a, b, *args):
    print(a)
    print(b)
    print(args)

process(1, 2, 3, 4, 5)
```

Output:

```text
1
2
(3, 4, 5)
```

Binding:

```text
a    → 1
b    → 2
args → (3, 4, 5)
```

### Important

`args` is a tuple.

```python
type(args)
# <class 'tuple'>
```

---

# 6. `**kwargs`

`**kwargs` collects additional keyword arguments into a **dictionary**.

```python
def process(a, b, **kwargs):
    print(a)
    print(b)
    print(kwargs)

process(1, 2, x=10, y=20)
```

Output:

```text
1
2
{'x': 10, 'y': 20}
```

Binding:

```text
a      → 1
b      → 2
kwargs → {"x": 10, "y": 20}
```

### Important

`kwargs` is a dictionary.

```python
type(kwargs)
# <class 'dict'>
```

---

# 7. `*args` and `**kwargs` Together

```python
def process(a, b, *args, c=10, **kwargs):
    print(a)
    print(b)
    print(args)
    print(c)
    print(kwargs)

process(1, 2, 3, 4, c=20, x=100, y=200)
```

Output:

```text
1
2
(3, 4)
20
{'x': 100, 'y': 200}
```

Binding:

```text
a      → 1
b      → 2
args   → (3, 4)
c      → 20
kwargs → {"x": 100, "y": 200}
```

# 8. Keyword-Only Arguments

A parameter can be explicitly made keyword-only using `*`.

```python
def create_user(name, *, age, role):
    print(name, age, role)
```

Valid:

```python
create_user("Mohit", age=25, role="AI Engineer")
```

Invalid:

```python
# ❌
create_user("Mohit", 25, "AI Engineer")
```

Here:

```text
name → positional or keyword
age  → keyword-only
role → keyword-only
```

### Practical use

Keyword-only parameters make APIs clearer:

```python
def query_database(sql, *, timeout=30, retries=3):
    ...
```

Usage:

```python
query_database(
    "SELECT * FROM users",
    timeout=10,
    retries=2
)
```

---

# 9. Positional-Only Arguments

Python supports positional-only parameters using `/`.

```python
def calculate(x, y, /, precision=2):
    return round(x + y, precision)
```

Valid:

```python
calculate(10, 20)
calculate(10, 20, precision=3)
```

Invalid:

```python
# ❌
calculate(x=10, y=20)
```

Because `x` and `y` are positional-only.

### Syntax

```text
/ → parameters before it are positional-only

* → parameters after it are keyword-only
```

Example:

```python
def func(a, b, /, c, d, *, e, f):
    ...
```

Means:

```text
a, b → positional-only

c, d → positional or keyword

e, f → keyword-only
```

# 10. Argument Unpacking

`*` can also be used while **calling** a function.

```python
def add(a, b, c):
    return a + b + c

values = (1, 2, 3)

print(add(*values))
# 6
```

`*values` unpacks:

```text
(1, 2, 3)
     ↓
add(1, 2, 3)
```

---

## Dictionary Unpacking

```python
def greet(name, role):
    print(name, role)

data = {
    "name": "Mohit",
    "role": "AI Engineer"
}

greet(**data)
```

Equivalent to:

```python
greet(name="Mohit", role="AI Engineer")
```

---

# 11. Collection vs Unpacking

Important distinction:

### Function definition

```python
def func(*args):
    ...
```

→ collects positional arguments.

```python
def func(**kwargs):
    ...
```

→ collects keyword arguments.

### Function call

```python
func(*values)
```

→ unpacks positional arguments.

```python
func(**data)
```

→ unpacks keyword arguments.

# 12. Default Arguments

A parameter can have a default value.

```python
def greet(name="Guest"):
    print(name)

greet()
# Guest

greet("Mohit")
# Mohit
```

The default is used when the caller doesn't provide that argument.

---

# 13. Mutable Default Argument Trap

This is a classic Python interview question.

Consider:

```python
def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item(1))
print(add_item(2))
print(add_item(3))
```

Output:

```text
[1]
[1, 2]
[1, 2, 3]
```

## Why?

The default:

```python
items=[]
```

is created **once when the function definition is executed**, not once per function call.

The function stores this default object.

Conceptually:

```text
Function definition
        ↓
     items = []
        ↓
   same list object
        │
        ├── call 1 → [1]
        ├── call 2 → [1, 2]
        └── call 3 → [1, 2, 3]
```

You can inspect it:

```python
print(add_item.__defaults__)
```

After calls it can contain:

```text
([1, 2, 3],)
```

---

# 14. What If a Value Is Explicitly Provided?

```python
def add_item(item, items=[]):
    items.append(item)
    return items

a = add_item(1)

b = add_item(2, ["A", "B"])

c = add_item(3)
```

The second call explicitly provides a list:

```python
add_item(2, ["A", "B"])
```

Therefore, the default list is **not used**.

Results:

```python
a
# [1, 3]

b
# ["A", "B", 2]

c
# [1, 3]
```

`a` and `c` refer to the same default list.

```python
a is c
# True
```

---

# 15. Correct Pattern for Mutable Defaults

Use `None`:

```python
def add_item(item, items=None):
    if items is None:
        items = []

    items.append(item)
    return items
```

Now each call creates a new list when needed:

```python
print(add_item(1))
# [1]

print(add_item(2))
# [2]

print(add_item(3))
# [3]
```

### Interview-ready explanation

> Default argument expressions are evaluated once when the function is defined. Therefore, a mutable default object such as a list is reused across calls. A common solution is to use `None` as a sentinel and create the mutable object inside the function.

# 16. Key Interview Points

### Functions

* Functions are first-class objects.
* Functions can be assigned to variables.
* Functions can be passed to other functions.
* Functions can return other functions.

### Arguments

```text
*args   → tuple
**kwargs → dict
```

### Unpacking

```text
*tuple → positional arguments
**dict → keyword arguments
```

### Parameters

```text
/ → positional-only
* → keyword-only
```

### Defaults

* Default values are evaluated when the function is defined.
* Avoid mutable defaults such as `[]`, `{}`, or `set()`.

### Core Interview Distinction

```python
f = function
```

→ reference to function.

```python
f = function()
```

→ execute function and store its return value.

# Python Topic 2.3 — Closures

## 1. What is a Closure?

A **closure** is a function that:

1. Is defined inside another function.
2. References a variable from the enclosing function's scope.
3. Continues to retain access to that variable even after the enclosing function has finished executing.

Example:

```python
def outer():
    x = 10

    def inner():
        return x

    return inner


f = outer()

print(f())  # 10
```

Here:

* `inner` is defined inside `outer`.
* `inner` references `x`.
* `outer()` finishes execution.
* However, `f()` can still access `x`.

That retained environment is the **closure**.

---

# 2. How the Closure Works

Consider:

```python
def outer(x):
    def inner(y):
        return x + y

    return inner


f = outer(10)
print(f(5))  # 15
```

Conceptually:

```text
outer(10)
   │
   ├── x = 10
   │
   └── inner()
          │
          └── closure → x = 10

f ─────────────→ inner()
```

When:

```python
f(5)
```

is executed:

```text
y = 5
x = 10   ← captured from enclosing scope

10 + 5 = 15
```

The important point:

> `f` references the `inner` function, and that function carries a closure containing the captured variable.

`f` itself is not the closure cell.

---

# 3. Closure vs Nested Function

A nested function alone is **not necessarily a closure**.

Example:

```python
def outer():
    def inner():
        return 10

    return inner
```

`inner` is a nested function, but it isn't capturing an enclosing variable.

A proper closure:

```python
def outer():
    x = 10

    def inner():
        return x

    return inner
```

Here `inner` captures `x`.

Therefore:

> A closure is a nested function that retains access to variables from its enclosing scope.

---

# 4. Closures Retain State

Closures can be used to maintain state without using global variables.

Example:

```python
def create_multiplier(n):

    def multiply(x):
        return x * n

    return multiply


double = create_multiplier(2)
triple = create_multiplier(3)

print(double(5))  # 10
print(triple(5))  # 15
```

Conceptually:

```text
double
  │
  └── closure → n = 2


triple
  │
  └── closure → n = 3
```

Each invocation of `create_multiplier()` creates its own enclosing scope and therefore its own captured state.

---

# 5. Each Closure Has Independent State

Example:

```python
def make_counter():

    count = 0

    def counter():
        nonlocal count
        count += 1
        return count

    return counter


c1 = make_counter()
c2 = make_counter()

print(c1())  # 1
print(c1())  # 2
print(c2())  # 1
print(c1())  # 3
```

Output:

```text
1
2
1
3
```

Why?

```text
c1 ──→ counter ──→ closure cell → count = 3

c2 ──→ counter ──→ closure cell → count = 1
```

`c1` and `c2` were created by **different invocations** of `make_counter()`, so they have separate closure environments.

---

# 6. Reading a Captured Variable

A closure can read an enclosing variable without any special keyword.

```python
def outer():
    x = 10

    def inner():
        return x

    return inner
```

This works because `inner()` doesn't assign to `x`.

Python looks outward:

```text
inner local scope
      ↓
enclosing outer scope
      ↓
x = 10
```

---

# 7. `nonlocal`

`nonlocal` is used when an inner function needs to **rebind/modify a variable belonging to an enclosing function scope**.

Example:

```python
def make_counter():

    count = 0

    def counter():
        nonlocal count
        count += 1
        return count

    return counter
```

Now:

```python
c = make_counter()

print(c())  # 1
print(c())  # 2
print(c())  # 3
```

`nonlocal` tells Python:

> "Use the `count` from the nearest enclosing function scope instead of creating a new local `count`."

---

# 8. Why Does `nonlocal` Matter?

Consider:

```python
def make_counter():

    count = 0

    def counter():
        count += 1
        return count

    return counter
```

This raises:

```text
UnboundLocalError
```

Why?

Because:

```python
count += 1
```

is conceptually:

```python
count = count + 1
```

The assignment causes Python to treat `count` as local to `counter()`.

Then Python effectively tries:

```python
count = count + 1
```

But the local `count` doesn't have a value yet.

Therefore:

```text
UnboundLocalError
```

---

# 9. `nonlocal` vs No `nonlocal`

### Reading:

```python
def outer():
    x = 10

    def inner():
        return x

    return inner
```

Works.

### Rebinding:

```python
def outer():
    x = 10

    def inner():
        x += 1

    return inner
```

Fails.

### Rebinding with `nonlocal`:

```python
def outer():
    x = 10

    def inner():
        nonlocal x
        x += 1

    return inner
```

Works.

---

# 10. Mutation vs Rebinding

This is an important Python interview distinction.

Consider:

```python
def outer():
    items = []

    def inner():
        items.append(10)

    return inner
```

This works without `nonlocal`.

Why?

Because:

```python
items.append(10)
```

**mutates the existing list object**.

It does not rebind the variable `items`.

Conceptually:

```text
items ─────→ []

inner()
   │
   └── append(10)
          ↓
       [10]
```

But:

```python
items = items + [10]
```

is reassignment/rebinding.

Therefore it needs:

```python
nonlocal items
```

Example:

```python
def outer():
    items = []

    def inner():
        nonlocal items
        items = items + [10]

    return inner
```

### Interview table

| Operation          | `nonlocal` required? |
| ------------------ | -------------------- |
| `x += 1`           | Yes                  |
| `x = something`    | Yes                  |
| `x = x + 1`        | Yes                  |
| `x.append(...)`    | No                   |
| `x.update(...)`    | No                   |
| `x["key"] = value` | No                   |

The distinction is:

```text
Mutation
   ↓
Modify existing object
   ↓
Usually no nonlocal

Rebinding
   ↓
Make the variable refer to another object
   ↓
nonlocal required
```

---

# 11. `nonlocal` vs `global`

### `nonlocal`

Refers to a variable in an enclosing function scope.

```python
def outer():
    x = 10

    def inner():
        nonlocal x
        x += 1
```

Scope:

```text
inner()
  ↓
outer()
  ↓
x
```

### `global`

Refers to a variable in module/global scope.

```python
x = 10

def func():
    global x
    x += 1
```

Conceptually:

```text
global
  ↓
module scope


nonlocal
  ↓
enclosing function scope
```

---

# 12. Closure Cells

Python internally stores captured variables in **closure cells**.

Example:

```python
def outer():
    x = 10

    def inner():
        return x

    return inner


f = outer()
```

The function object can expose its closure:

```python
print(f.__closure__)
```

And:

```python
print(f.__closure__[0].cell_contents)
```

can show:

```text
10
```

The captured variable is stored in a cell rather than simply being copied as an ordinary local variable.

You can also inspect:

```python
f.__code__.co_freevars
```

For example, it may show:

```text
('x',)
```

This indicates that `x` is a **free variable** for the inner function.

### Interview-level understanding

You generally don't need to manipulate `__closure__` directly.

Just understand:

```text
function
   ↓
closure
   ↓
cell
   ↓
captured variable
```

---

# 13. Closure and Scope Lookup

Python follows lexical scoping.

For a variable referenced inside a function, conceptually think:

```text
Local
  ↓
Enclosing
  ↓
Global
  ↓
Built-in
```

This is the **LEGB** rule.

For closures, the important part is:

```text
Local → Enclosing
```

Example:

```python
def outer():
    x = 10

    def inner():
        return x

    return inner
```

`x` isn't local to `inner`, so Python finds it in the enclosing scope.

# 14. Late Binding

One of the most common closure interview traps.

Consider:

```python
functions = []

for i in range(3):

    def func():
        return i

    functions.append(func)

print(functions[0]())
print(functions[1]())
print(functions[2]())
```

Many people expect:

```text
0
1
2
```

But the output is:

```text
2
2
2
```

### Why?

Closures capture the **variable**, not a snapshot of its value at function creation time.

Conceptually:

```text
func1 ──┐
func2 ──┼──→ same variable i
func3 ──┘
             ↓
            2
```

After the loop:

```python
i = 2
```

When the functions are called, they look up `i` and get `2`.

This behavior is called **late binding**.

---

# 15. Fixing Late Binding

A common solution is to use a default argument.

```python
functions = []

for i in range(3):

    def func(i=i):
        return i

    functions.append(func)
```

Now:

```python
print(functions[0]())  # 0
print(functions[1]())  # 1
print(functions[2]())  # 2
```

Why?

Default arguments are evaluated when the function is created.

Therefore each function gets its own bound value:

```text
func1 → i = 0
func2 → i = 1
func3 → i = 2
```

---

# 16. Closure vs Global State

Closures can provide state without exposing a global variable.

Global-state approach:

```python
count = 0

def increment():
    global count
    count += 1
```

Closure approach:

```python
def make_counter():

    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment
```

The closure provides better encapsulation because the state isn't directly exposed as a global variable.

---

# 17. Practical Uses of Closures

Closures are useful for:

### 1. Stateful functions

```python
counter = make_counter()
```

### 2. Configuration

```python
def create_logger(prefix):

    def log(message):
        print(prefix, message)

    return log
```

### 3. Callbacks

A callback can retain configuration/context from the scope where it was created.

### 4. Decorators

Decorators heavily rely on:

* Higher-order functions
* Nested functions
* Closures

Example:

```python
def decorator(func):

    def wrapper():
        print("Before")
        func()
        print("After")

    return wrapper
```

The `wrapper` function closes over `func`.

This is why understanding closures makes decorators much easier.

---

# 18. Important Interview Traps

### Trap 1 — Nested function ≠ automatically closure

A nested function becomes a closure when it retains access to an enclosing variable.

### Trap 2 — Reading doesn't require `nonlocal`

```python
return x
```

is fine.

### Trap 3 — Rebinding requires `nonlocal`

```python
x += 1
```

requires `nonlocal` when `x` belongs to an enclosing function.

### Trap 4 — Mutation doesn't necessarily require `nonlocal`

```python
items.append(1)
```

mutates the object.

### Trap 5 — Closures don't necessarily capture a snapshot

Loop closures can exhibit late binding.

### Trap 6 — Different calls create different closure state

```python
c1 = make_counter()
c2 = make_counter()
```

`c1` and `c2` have independent captured state.

---

# 19. Interview-Ready Definition

If asked:

> "What is a closure in Python?"

A strong answer:

> "A closure is a function that retains access to variables from its enclosing lexical scope even after the enclosing function has finished execution. The captured variables are maintained through the function's closure cells. Closures are commonly used for encapsulated state, callbacks, configuration, and decorators."

---

# 20. Interview-Ready `nonlocal` Explanation

If asked:

> "Why do we need `nonlocal`?"

Answer:

> "`nonlocal` tells Python that an assignment should rebind a variable from the nearest enclosing function scope rather than create a new local variable. Without it, an operation like `count += 1` makes `count` local to the inner function, causing Python to try to read an uninitialized local variable and raise `UnboundLocalError`."

---

# 21. Key Takeaways

Remember these six points:

```text
1. Closure = function + retained enclosing environment

2. Captured variables are available even after
   the outer function returns.

3. Reading a captured variable doesn't require nonlocal.

4. Rebinding a captured variable requires nonlocal.

5. Mutating a captured mutable object usually doesn't
   require nonlocal.

6. Closures use late binding for free variables.
```

### Mental model

```text
Outer function
     │
     ├── local variable
     │
     └── inner function
             │
             └── closure
                   │
                   └── cell → captured variable
```

And:

```text
Read       → enclosing scope lookup
Rebind     → nonlocal
Mutate     → usually no nonlocal
Loop value → beware late binding
```
